r5r-infrastruktur — Service och tillgänglighet

Uppsättning av tillgänglighetsanalysen (restider till arbete/service) med R-paketet r5r (Rapid Realistic Routing, R5-motorn från Conveyal via rJava). Nätverket byggdes och verifierades 2026-07-01 och är körklart: walk/bike/car (OSM) + kollektivtrafik (GTFS) för fem sydsvenska län.

Status: KLART ✔

r5r-natverk/network.dat är byggd och testad. Verifierat: gatunät 3,67 milj. kanter / 1,46 milj. noder, transit 12 470 linjer / 45 383 hållplatser, trafik aktiv (t.ex. 2026-09-16: 1 163 aktiva turer), och ett restidstest WALK vs WALK+TRANSIT från Halmstad når Göteborg (230 min), Malmö (190), Växjö (337), Jönköping (395) med kollektivtrafik medan gång inte når dem, dvs. kollektivtrafik-routingen fungerar.

Studieområde

Fem län, sammanslagna till en polygon med 7,5 km buffert:

Java

r5r 2.4.0 bygger på R5 v7.5.1 och kräver JDK 21. Systemets Java var 1.8 (för gammalt). rJavaEnv::java_quick_install(version = 21) installerade Amazon Corretto 21 (utan adminrättigheter) i:

C:\Users\rrn508\AppData\Local\R\cache\R\rJavaEnv\installed\windows\x64\21

rJavaEnv skrev en projektlokal .Rprofile (i projektroten) som automatiskt sätter JAVA_HOME/PATH till Java 21 när R startas från projektet. Verifierat: Java 21.0.11, r5r 2.4.0. Kör därför alltid R från projektroten.

R5-motorns jar (r5-v7.5-1-...-all.jar, 61,5 MB) laddas ner automatiskt av r5r::build_network() vid första bygget och cachas i:

C:\Users\rrn508\AppData\Local\R\cache\R\r5r\r5_jar_v7.5.1\

OSM-vägnät

Källa: Geofabrik, hela Sverige (sweden-latest.osm.pbf, 771 MB), i lokal cache utanför OneDrive-synken:

%LOCALAPPDATA%\kapitelrapport-cache\osm\sweden-latest.osm.pbf

Beskärning till studieområdet: osmium-tool gick inte att installera i uppsättningsmiljön. Istället användes Osmosis 0.49.2 (OSM Foundations Java-verktyg, kräver ingen installation utöver Java som vi redan har), nedladdat till:

%LOCALAPPDATA%\kapitelrapport-cache\tools\osmosis-0.49.2\

Sverige-filen klipptes mot en till 284 hörn förenklad polygon (Douglas-Peucker 500 m i SWEREF99 TM) med completeWays=yes och JAVACMD_OPTIONS=-Xmx6G. Resultat: r5r-natverk/studieomrade-5lan.osm.pbf (238,7 MB). Se bearbetning_data/klipp_osm_osmosis.R för det reproducerbara steget.

Varför klippa (inte köra hela Sverige): R5 har en hårdkodad gräns på 975 000 km² bounding-box-utbredning; Sveriges avlånga bbox riskerar slå i taket. De fem sydliga länen ligger med god marginal under.

GTFS-kollektivtrafik

Källa: GTFS Sverige 2 (Samtrafiken), keyless spegling via Mobility Database (mdb-2661), licens CC0 1.0. Ett nationellt flöde täcker alla fem länens trafikbolag (Hallandstrafiken, Skånetrafiken, Västtrafik, Länstrafiken Kronoberg, Jönköpings Länstrafik). Ingen API-nyckel behövs.

Rensning (viktig): feeden använder utökade GTFS-route_types. R5 v7.5.1 stödjer dem UTOM Taxi-familjen (1500-serien) — route_type = 1501 (anropsstyrd närtrafik) får routingen att krascha (Taxi route_type code not supported). Dessa 488 rutter tas bort med korrekt kaskad via gtfstools (de är demand-responsive och hör inte hemma i en fast-schema-analys). Se bearbetning_data/hamta_gtfs.R. Resultat: r5r-natverk/gtfs_sverige.zip (55 MB), 8 479 kvarvarande rutter (typerna 700/106/102/702/101/1000/900/401).

Bygga nätverket

bearbetning_data/bygg_r5r_natverk.R sätter options(java.parameters="-Xmx8G") FÖRE library(r5r), kör build_network() (ej det deprecerade setup_r5()) med elevation="NONE", overwrite=TRUE, och verifierar bygget. Byggtid ~2 min. Skapar network.dat (~342 MB) m.fl. artefakter i r5r-natverk/.

bearbetning_data/verifiera_transit.R laddar det byggda nätverket och kör check_transit_availability() + ett WALK vs WALK+TRANSIT-restidstest.

Att tänka på

  • OneDrive-synk: r5r-natverk/ är nu ~1,1 GB (pbf + network.dat + .mapdb). OneDrive försöker synka detta. Överväg att exkludera mappen från synk (eller flytta hela r5r-natverk/ till den lokala cachen och peka data_path dit) om synken blir tung. De stora filerna kan alltid återskapas av skripten.
  • GTFS-datum: kalendern täcker 2026-06-15 t.o.m. 2027-05-31. Sätt analysdatumet (avgångstid) till en vanlig vardag i det intervallet, annars hittas inga turer. check_transit_availability() visar aktiva datum.
  • Restidstestets råa testpunkter: smoke-testet använder grova stadskoordinater; ett par värden (t.ex. Varberg, Falkenberg) blev udda pga snapping/avgångstid. Riktig analys bör snappa origin/destination till vettiga punkter (befolkningsgrid, arbetsställen).
  • GTFS-varningar: ~2 100 icke-fatala GTFS-fel (mest saknade shapes) vid bygget; r5r::get_gtfs_errors() listar dem. De hindrar inte routing.

Nästa steg

  1. Bygg analysskripten (restidsmatriser, tillgänglighetsindex) i bearbetning_data/ med det byggda nätverket.
  2. Valfritt: skaffa gratis Trafiklab-nyckel (developer.trafiklab.se/register) för GTFS Regional per operatör om linjegeometri (shapes) eller enskilda län behövs — behövs INTE för restidsanalysen.
