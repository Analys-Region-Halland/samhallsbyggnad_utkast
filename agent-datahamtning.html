Aktiveras när: data ska hämtas från API (SCB, Kolada, FoHM, Tillväxtverket, Trafikanalys) eller importeras från fil.

Grundprincip: Eliminera till total

Varje API-anrop ska reducera dimensioner till totalnivå. Behåll BARA geografi + tid. Allt annat elimineras om det inte uttryckligen efterfrågas:

  • Kön → "T" (Kolada) eller "1+2" (SCB). Aldrig "1" och "2" separat om det inte uttryckligen begärts.
  • Ålder → Fördefinierad grupp (t.ex. "20-64 år"), aldrig ettårsklasser.
  • Bransch/sektor → "Samtliga branscher" eller totalkod.
  • Utbildningsnivå → Total om inte ämnet kräver uppdelning.

Varför: SCB returnerar korsningar av ALLA dimensioner. Frågar du om 290 kommuner × 5 åldersgrupper × 2 kön × 10 år = 29 000 rader istället för 2 900. Det ger datablåsa, långsamma hämtningar och 100 000-cellsgränsen nås snabbt.

I pxweb (SCB/FoHM) implementeras detta genom att utelämna dimensionen ur queryn. Inkludera BARA de dimensioner du vill behålla i resultatet — utelämnade dimensioner summeras automatiskt av API:t. Ange aldrig en “totalkod” (t.ex. “1+2”) utan att först verifiera i metadata att koden faktiskt finns i tabellen.

Steg-för-steg-arbetsordning

1. Identifiera rätt KPI/tabell INNAN du skriver kod.

  • Kolada: Sök i lokalt KPI-register (data/kolada-kpi-register.rds) med rKolada::get_kpi() eller grep. Registret har 6 200+ indikatorer. Kontrollera att KPI:n har data för önskade år och kommuner.
  • SCB: Navigera tabellträdet via pxweb::pxweb_get("https://api.scb.se/OV0104/v1/doris/sv/ssd/{ämne}/"). Inspektera ALLTID tabellens metadata (variabelkoder, tillgängliga perioder, regionkoder) innan du bygger en query.

2. Inspektera metadata FÖRST — skriv query SEDAN.

SCB-tabeller har variabelkoder som inte alltid är uppenbara. Gör detta innan varje ny tabell:

# Hämta tabellens metadata
meta <- pxweb::pxweb_get("https://api.scb.se/OV0104/v1/doris/sv/ssd/AM/AM0210/AM0210B/ArbStatusAr")

# Skriv ut varje variabel med sina kodvärden
for (var in meta$variables) {
  cat("\n===", var$code, "(", var$text, ") ===\n")
  for (i in seq_len(min(10, length(var$values)))) {
    cat("  ", var$values[i], " = ", var$valueTexts[i], "\n")
  }
  if (length(var$values) > 10) cat("  ... (", length(var$values), "värden totalt)\n")
}

Kontrollera: - Vilken kod har Region-variabeln? (Ofta "Region", ibland "Kommun" eller "Lan") - Vilken kod har tidsvariabeln? (Ofta "Tid", ibland "År") - Vilka ContentsCodes finns? (Mätvärdet — t.ex. "AM0401I1" = antal sysselsatta) - Finns kön som dimension? Om ja, vilken kod har total? ("1+2", "T", "samtliga") - Vilka perioder finns? Matcha mot vad du vill hämta.

3. Bygg queryn med explicita värden — och ELIMINERA onödiga dimensioner.

pxweb har ett inbyggt mönster: utelämna en dimension från queryn så summerar API:t automatiskt över den dimensionen. Det kallas “eliminate” och är det korrekta sättet att hämta totaler — INTE att ange en totalkod som “1+2” (som ofta inte finns).

# RÄTT — eliminera kön och ålder genom att UTELÄMNA dem ur queryn
# pxweb summerar automatiskt: alla kön, alla åldrar, alla civilstånd → total
query <- list(
  Region       = c("1315", "1380", "1381", "1382", "1383", "1384", "13", "00"),
  ContentsCode = c("BE0101N1"),     # Bara det mätvärde vi vill ha
  Tid          = as.character(2015:2024)
)
# Kön, Ålder, Civilstand → UTELÄMNADE = automatiskt eliminerade (summerade)

# FEL — ange totalkod som kanske inte finns
query <- list(
  Region = c("1380"), Kon = c("1+2"),   # "1+2" finns inte i alla tabeller!
  ContentsCode = c("BE0101N1"), Tid = c("2024")
)

# FEL — wildcard ("*") ger ALL data, alla regioner, alla kön
query <- list(Region = c("*"), Kon = c("*"), Tid = c("*"))

# FEL — hämta alla delgrupper och summera i R (onödigt, spränger cellgränsen)
query <- list(
  Region = c("1380"), Kon = c("1", "2"), Alder = as.character(0:100), ...
)

Tumregel: Inkludera BARA de dimensioner du vill ha kvar i resultatet. Allt du utelämnar summeras automatiskt av API:t. Det ger: - Färre celler → håller dig under 100 000-gränsen - Korrekt aggregering (SCB:s egen summering, inte din) - Enklare kod

När ska du INTE eliminera? När du uttryckligen behöver delgrupper:

# Behöver kön-uppdelning → inkludera Kon i queryn
query <- list(
  Region       = c("1380"),
  Kon          = c("1", "2"),        # Vill ha män och kvinnor separat
  ContentsCode = c("BE0101N1"),
  Tid          = as.character(2015:2024)
)

4. Hämta med kodformat — ALDRIG textformat.

px_data <- pxweb::pxweb_get(url = tabell_url, query = pxweb::pxweb_query(query))

df <- as.data.frame(px_data,
  column.name.type    = "code",    # "Region" inte "region"
  variable.value.type = "code",    # "1380" inte "Halmstad"
  stringsAsFactors    = FALSE
)

Varför "code": Koder är stabila. Textlabels ändras mellan SCB-uppdateringar. Koder möjliggör tillförlitliga joins.

5. Transformera regionkoder till Kolada-format.

SCB och Kolada använder olika kodlängder. Standardisera ALLTID till 4-siffriga koder:

df <- df |>
  mutate(kommun_kod = case_when(
    Region == "00"        ~ "0000",                    # Riket
    nchar(Region) == 2    ~ paste0("00", Region),      # Län → 4 siffror (t.ex. "13" → "0013")
    TRUE                  ~ Region                      # Kommuner redan 4 siffror
  ))

6. Filtrera till kända kommuner.

HALLAND_KODER <- c("1380", "1381", "1382", "1383", "1384", "1315")
REGION_KODER  <- c("0013")   # Region Halland
RIKET_KOD     <- c("0000")   # Nationellt

kanda_koder <- c(HALLAND_KODER, REGION_KODER, RIKET_KOD)

df <- df |> filter(kommun_kod %in% kanda_koder)

7. Spara som RDS — rör aldrig rådatan igen.

saveRDS(df, "data/radata-{tema_id}.rds")

FoHM (Folkhälsomyndigheten) — specifika regler

Endpoint: https://fohm-app.folkhalsomyndigheten.se/Folkhalsodata/api/v1/sv Använder PxWeb-format (samma mönster som SCB), men med skillnader:

  • Rullande perioder: Data rapporteras ofta som "2021-2024" (4-årsmedelvärde). Konvertera till slutår: as.integer(sub(".*-", "", period_str)).
  • Konfidensintervall: Många tabeller har en KI-variabel med tre nivåer (andel, lower, upper). Pivota till separata kolumner:
df |> pivot_wider(
  id_cols    = c(region, gender, year),
  names_from = ki_typ,
  values_from = varde
)
# Ger kolumner: varde, ki_lower, ki_upper
  • Rate limit: Lägg in Sys.sleep(0.5) mellan anrop.
  • Könskoder varierar per tabell: "00" = total i vissa, "1+2" i andra. Kontrollera metadata.
  • Felhantering: Wrappa varje tabell i tryCatch() — FoHM-API:t är mindre stabilt.

Tillväxtverket — specifika regler

Data: Tab-separerade textfiler (TSV), Latin-1-kodning, CC0-licens. Källa: https://oppnadata.tillvaxtverket.se/data/inkvartering/

  • Geografinivåer: Kommun (4-siffrigt), Län (2-siffrigt → padda till 4), Riket (0000).
  • Härledda KPI:er beräknas i R (beläggningsgrad, intäkt per gästnatt etc.).
  • Kräver att befolkningstemat körts först — kommun-register.rds måste finnas.

Trafikanalys — specifika regler

Endpoint: https://api.trafa.se/api/data Icke-PxWeb REST API. Query-format: pipe-separerade parametrar.

query_str <- "T10026|itrfslut|ar:2023|reglan:13|regkom"
url <- paste0(base_url, "?query=", utils::URLencode(query_str, reserved = TRUE))
resp <- httr::GET(url, httr::timeout(60))
  • Kontrollera HTTP-status (status_code != 200 → stoppa).
  • Kontrollera parsed$Errors-fältet (API returnerar ibland 200 med felmeddelande i body).
  • Trafikanalys returnerar kommunnamn, inte koder. Mappa via kommun-register.
  • Rensa numeriska värden: as.numeric(gsub("[^0-9.,-]", "", gsub(",", ".", value_str))) — hanterar nbsp, tusentalsseparatorer.

Standardisera till samma format som API-data:

Oavsett filformat, omvandla ALLTID till output-kontraktet innan du sparar:

radata <- df |>
  transmute(

    kommun_kod = as.character(Kommunkod),                # Alltid character
    kommun_namn = Kommun,
    kommun_typ = if_else(nchar(kommun_kod) <= 2, "L", "K"),
    ar         = as.integer(År),

    varde      = as.numeric(gsub(",", ".", Antal)),      # Hantera decimalkomma

    ki_upper   = NA_real_

  # Standardisera regionkoder till 4-siffrig
  mutate(kommun_kod = case_when(
    kommun_kod == "00"     ~ "0000",
    nchar(kommun_kod) == 2 ~ paste0("00", kommun_kod),
    .default = kommun_kod
  ))

Cachestrategi

All cachning styrs av R/gemensam/cache.R. Metadatafil per tema: data/hamtning-meta-{tema_id}.rds.

Beslutsträd:
├── tvinga = TRUE           → Full hämtning, ignorera cache
├── Ingen cachefil finns    → Full hämtning
├── KPI-lista ändrad        → Full hämtning (setequal-check)
├── Nya perioder finns      → Inkrementell hämtning (bara nya år)
├── Cache < 30 dagar        → Hoppa över (använd befintlig)
├── Cache ≥ 30 dagar        → Kontroll-hämtning (1 KPI, 1 år, riket)
│   ├── Nya data finns      → Inkrementell hämtning
│   └── Inga nya data       → Uppdatera tidsstämpel, hoppa över

Metadata som sparas:

list(
  tidsstampel   = Sys.time(),

  perioder      = c("2015", "2016", ..., "2024"),
  senaste_period = 2024L,
  antal_rader   = 4800

Kvalitetssäkring efter hämtning

Kör ALLTID efter en hämtning innan du går vidare till bearbetning:

# 1. Dimensionskontroll — har vi rätt antal rader?
forvantade <- length(kpi_ids) * length(kommun_koder) * length(perioder)
cat("Hämtade:", nrow(df), "rader. Förväntat:", forvantade, "\n")
if (nrow(df) < forvantade * 0.8) warning("Fick <80% av förväntade rader")

# 2. Saknade kommuner
saknade_kommuner <- setdiff(kommun_koder, unique(df$kommun_kod))
if (length(saknade_kommuner) > 0) {
  warning("Saknade kommuner: ", paste(saknade_kommuner, collapse = ", "))
}

# 3. Saknade KPI:er
saknade_kpi <- setdiff(kpi_ids, unique(df$kpi_id))
if (length(saknade_kpi) > 0) {
  warning("Saknade KPI:er: ", paste(saknade_kpi, collapse = ", "))
}

# 4. Saknade år
saknade_ar <- setdiff(as.character(perioder), as.character(unique(df$ar)))
if (length(saknade_ar) > 0) {
  warning("Saknade år: ", paste(saknade_ar, collapse = ", "))
}

# 5. NA-kontroll
na_andel <- mean(is.na(df$varde))
if (na_andel > 0.1) warning("Hög andel saknade värden: ", round(na_andel * 100, 1), "%")

# 6. Dubbletter
dubb <- df |> group_by(kpi_id, kommun_kod, ar) |> filter(n() > 1) |> nrow()
if (dubb > 0) warning("Dubbletter funna: ", dubb, " rader")

# 7. Rimlighetsintervall (procent-KPI:er ska vara 0–100)
procent_kpier <- df |> filter(enhet == "procent" & (varde < 0 | varde > 100))
if (nrow(procent_kpier) > 0) warning("Procentvärden utanför 0-100: ", nrow(procent_kpier), " rader")
